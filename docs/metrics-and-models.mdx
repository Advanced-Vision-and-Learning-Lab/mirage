## Metrics

The demo exposes these metric choices:

| Metric | What the implementation evaluates | Notes |
| --- | --- | --- |
| CHAIR | Object mentions in generated image captions against annotated objects. | Uses COCO synonym handling for COCO; Visual Genome uses its object names without stopwords, colours, and other non-object strings. |
| POPE | Yes/no answers to questions about objects present or absent in an image. | The demo uses random negative-object sampling by default. |
| ROPE | Object recognition for numbered, boxed image regions. | The demo uses five boxes and asks the model to identify each region. Before the strict exact-label match, the extractor removes markdown, quotes, parenthetical asides, and lead-ins such as "The object inside box 1 appears to be". |
| THRONE | Caption object predictions against the dataset's object categories. | Uses the loaded dataset's category or object-name list. Choose the evaluator with `--throne-evaluator` and limit questions to ground-truth objects plus sampled distractors with `--throne-distractor-ratio`. |
| FaithScore | Faithfulness checks on generated captions. | Requires a local LLaMA model path via `--llama-model` or `MIRAGE_LLAMA_MODEL_PATH`, plus a PaliGemma verification model. |
| NOPE | Scores responses to the NOPE question set. | Requires pre-generated Turn 2 responses via `--nope-turn2`; Turn 1 input is optional. |

Metric availability can depend on the dataset path and local files. For example, ROPE needs annotated boxes, while NOPE reads its response JSON input rather than the normal dataset caption path.

## Models

The prediction factory supports these local vision-language models:

| Key | Default checkpoint | Path override |
| --- | --- | --- |
| `paligemma` | `google/paligemma-3b-mix-224` | `MIRAGE_PALIGEMMA_MODEL_PATH` |
| `qwen2vl` | `Qwen/Qwen2-VL-2B-Instruct` | `MIRAGE_QWEN_MODEL_PATH` |
| `gemma4-e4b` | `google/gemma-4-E4B-it` | `MIRAGE_GEMMA4_E4B_MODEL_PATH` |
| `gemma4-12b` | `google/gemma-4-12B-it` | `MIRAGE_GEMMA4_12B_MODEL_PATH` |
| `ministral3-8b` | `mistralai/Ministral-3-8B-Instruct-2512-BF16` | `MIRAGE_MINISTRAL3_8B_MODEL_PATH` |
| `ministral3-14b` | `mistralai/Ministral-3-14B-Instruct-2512-BF16` | `MIRAGE_MINISTRAL3_14B_MODEL_PATH` |
| `aya-vision-8b` | `CohereLabs/aya-vision-8b` | `MIRAGE_AYA_VISION_8B_MODEL_PATH` |
| `muse-glimmer-30b` | `meta-models/Muse-Glimmer-30B` | `MIRAGE_MUSE_GLIMMER_30B_MODEL_PATH` |
| `gemma4-e4b-think`, `gemma4-12b-think` | Same as the Gemma 4 keys, thinking on | Same as the Gemma 4 keys |

The Gemma 4, Ministral 3, and Aya Vision keys share one wrapper, `models/hf_chat_vlm.py`. It sends one image and one text turn through the processor's chat template, decodes only the new tokens, and runs with thinking disabled (`enable_thinking=False`). The `gemma4-e4b-think` and `gemma4-12b-think` keys load the same Gemma 4 checkpoints with thinking enabled. They add 1,024 tokens to each metric's `max_new_tokens`, shared by the thought and the answer, and drop the thought before scoring. If the thought does not close within that budget, the wrapper logs a warning and returns the truncated thought as the response, and the metric parses it like any other answer. Aya Vision is a gated, non-commercial (CC-BY-NC) checkpoint; accept its license on Hugging Face before downloading it.

`muse-glimmer-30b` uses the same wrapper through `MuseGlimmerVLM`. Muse Glimmer has no switch that turns thinking off: its chat template only sets a reasoning strength (low, medium, high, or xhigh), and after `<|start|>assistant` the model chooses a reasoning channel (`to=self`) or an answer channel (`to=user`). Mirage keeps `Reasoning strength: low` in the system turn and prefills the answer channel (` to=user<|message|>`), the same turn the template itself writes for an answer, so the model answers without reasoning. The template's current date is pinned to 2026-10-15 so prompts do not change from day to day. Images are resized with PIL LANCZOS to the size the image processor would choose, because the processor falls back to BICUBIC with torchvision older than 0.27; its own resize then leaves the pixels unchanged.

These are the model keys currently supported by `demo.py`. A different checkpoint can be used through the model-path override only when it is compatible with that wrapper. DeepSeek-VL is not currently supported; adding it requires a model wrapper and factory registration before it can be selected as a separate model key. See [Maintain the docs](/maintaining-docs) for the implementation handoff requirements.

Set `MIRAGE_VL_MODEL` to choose the default model when `--model` is omitted. Models are loaded for inference at runtime; model weights are not included in the repository.

## Result caching

Predictions pass through the `predict` package, which wraps model inference with a response cache. Cache identity and storage are implemented in `predict/identity.py` and `predict/cache.py`; the demo's SLURM example sets `MIRAGE_CACHE_DIR` to a job-specific directory.
